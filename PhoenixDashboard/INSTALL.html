Phoenix team log — setting up a laptop

Steps 1–5 are a grown-up job, once per laptop. Step 6 is what the kids do every week.

1. Install Node.js

Go to nodejs.org and take the big green LTS button. Click Next through the installer.

2. Install Git

Windows: git-scm.com — Next through it, all the defaults are fine. Install this even if you already have GitHub Desktop: GitHub Desktop keeps its own private copy of Git that the tool cannot see.
Mac: open Terminal, type git --version. If it offers to install developer tools, say yes.

3. Get the team folder

Install GitHub Desktop, sign in with the team GitHub account, and clone PiedmontFLLPhoenix/bioglow2026.

Clone it wherever you like. Documents is fine, C:\FLL is fine. The tool works out where the team folder is from its own location, so every laptop can keep it somewhere different. Write down where you put it — step 5 needs it.

4. Sign this laptop in to GitHub

Open Terminal (Mac) or Git Bash (Windows) and run these two lines, changing the name:

git config --global user.name "Phoenix Laptop 2"
git config --global user.email "phoenix.team@example.com"

Then, in GitHub Desktop: change any small thing (add a line to README.md), press Commit, then press Push.

Do not skip that push. Pushing once by hand is what makes GitHub remember this laptop. If you skip it, every kid's save will fail. The tool will say “This computer is not set up yet” — that means come back here.

5. Point Chrome's downloads at the missions folder

Open the missions folder inside the team folder in Explorer, click the address bar, and copy the path. Then: Chrome → Settings → Downloads → Location → paste it, and turn off “Ask where to save each file”.

Now when a kid clicks Backup in Pybricks, the program lands straight in the team folder.

6. Start it, and make a proper shortcut

Double-click PhoenixDashboard → start-team-log.bat (on a Mac, start-team-log.command).

A black window opens and the browser goes to the tool by itself. Leave the black window open — closing it turns the tool off.

To give the team a real icon instead of a .bat file:

  1. Right-click start-team-log.bat → Send to → Desktop (create shortcut)
  2. Rename the shortcut to Team log
  3. Right-click it → Properties → Change Icon → Browse
  4. Pick PhoenixDashboard\team-log.ico from the team folder, then OK, then OK
  5. Drag the shortcut to the taskbar, or right-click it → Pin to taskbar


The browser tab shows the same icon.

What the kids do each session

  1. Double-click Team log.
  2. Press Update my folders from GitHub to get what the rest of the team did.
  3. Work in Pybricks. Click Backup whenever a program is worth keeping.
  4. Write the entry: tick what they worked on, then who, what we tried, what happened, what next.
  5. Press Save and send to GitHub and answer the two questions.
  6. Read engineering blog shows the whole season, newest first.

If something goes wrong

The tool explains itself in plain words. A red message that mentions the coach means the work is safe on that laptop and nothing is lost — it just hasn't reached GitHub yet. Pressing the button again later usually sends it.

The small grey text under a red message is the real technical detail. That's for the coach.

A yellow message means the tool updated itself and needs restarting: close the black window and start Team log again.

One rule the software can't enforce

One person per mission program. Pybricks block files cannot be combined — if two laptops edit the same program, one of them loses their work. Decide who owns which mission. Different missions on different laptops at the same time is completely fine.
